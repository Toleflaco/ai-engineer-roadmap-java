- **Fecha:** 2026-07-24

## Contexto

Sesión repartida en dos bloques, mañana y tarde. El bloque de mañana se dedicó al arranque técnico del primer proyecto del roadmap, `document-analyzer-ai`. El bloque de tarde se dedicó a documentación del proyecto nuevo y a infraestructura personal de gestión de secretos.

## Qué se hizo

Se creó el repositorio `document-analyzer-ai` como Proyecto 1 del roadmap. Se migró el remoto de HTTPS a SSH desde el inicio, siguiendo la convención ya establecida en los repos anteriores. Se hizo el scaffold inicial con Spring Boot 4.1.0 y Spring AI 2.0.0, y se configuró la integración con Anthropic usando el patrón `${ANTHROPIC_API_KEY}` en la configuración para evitar filtrar la clave en git.

Se implementó el primer endpoint `/chat`, usando `ChatClient` en modo stateless, y se verificó empíricamente la primera llamada real desde Spring Boot a Claude. Sobre ese mismo endpoint se hicieron experimentos empíricos variando el parámetro `temperature` del `ChatClient`.

Por la tarde se escribió el `CLAUDE.md` del proyecto `document-analyzer-ai`, con nueve secciones. Se redactó también el README del proyecto delegando la tarea a Claude Code, primera vez que se usa la herramienta para una tarea de redacción real en lugar de código. Adicionalmente, se instaló Bitwarden: cuenta creada, extensión de Chrome instalada, CLI instalado y primer secreto guardado en el vault.

Al cierre de la sesión, `document-analyzer-ai` acumulaba seis commits.

## Decisiones y aprendizajes

Se decidió migrar el remoto a SSH desde la creación del repositorio, en lugar de arrancar por HTTPS como ocurrió con el hub en la Sesión 01. Al haber ya un fallo de autenticación documentado en esa sesión anterior, se aplicó la lección directamente en lugar de repetir el mismo diagnóstico.

Se adoptó el patrón `${ANTHROPIC_API_KEY}` como forma de gestión de secretos en la configuración de Spring AI, para que la clave nunca quede en texto plano dentro del repositorio.

Se decidió que el primer endpoint de contacto con Claude fuera stateless, usando `ChatClient` sin memoria de conversación. Esto deja la gestión de estado (`ChatMemory`) como paso posterior explícito, en lugar de mezclar ambos conceptos en la primera implementación.
