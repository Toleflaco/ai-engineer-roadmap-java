# Sesión 01 — Creación del repositorio hub

- **Fecha:** 2026-07-23
- **Fase:** 1 (Fundamentos LLM + Spring AI core)
- **Duración:** ~2 h
- **Estado del roadmap:** Fase 0 cerrada previamente. Fase 1 en curso, sin código todavía.

## Contexto

Primera sesión formal del roadmap AI Engineer. La Fase 0 (prerrequisitos Java + Spring Boot) se dio por cerrada con base en los dos proyectos previos (`task-manager-api` y `task-manager-microservices`), que cubren de sobra los fundamentos exigidos por la Fase 0 del roadmap. La sesión de hoy se dedicó íntegramente a la infraestructura documental del roadmap, no a contenido técnico de IA.

## Qué se hizo

Se creó el repositorio `ai-engineer-roadmap-java` como hub público de la formación, con licencia MIT, `.gitignore` de Java y una estructura de tres ficheros iniciales: `README.md`, `CLAUDE.md` y `LICENSE`. Se decidió que el hub no contendría código, solo documentación: `README.md` como portada del roadmap, `CLAUDE.md` como instrucciones para Claude Code, y dos carpetas futuras (`bitacora/` y `decisions/`) que se materializarán conforme lleguen sus contenidos.

Se redactó el `CLAUDE.md` completo con siete secciones: propósito, cómo trabajar aquí, estructura, convenciones, instrucciones específicas para Claude Code, relación con los repos de proyecto y comandos habituales. Las convenciones se heredaron parcialmente de `task-manager-api` (formato ISO 8601, ADRs Nygard) pero se adaptaron al hecho de que este repo es de documentación: se abandonaron los conventional commits (`feat:`, `docs:`) por commits en español a secas, se abandonó el flujo de ramas por commits directos a `main`, y se prohibió explícitamente que Claude Code proponga código Java desde este repo.

Se redactó el `README.md` con el roadmap completo en tabla (siete fases con estado), la descripción de los cuatro proyectos entregables uno a uno, y un bloque de contexto con enlaces a LinkedIn y a los repos previos. Se cuidó el SEO técnico mencionando explícitamente las tecnologías clave (MCP, RAG multi-tenant, Prometheus + Grafana, ECS Fargate).

Durante la sesión surgió un fallo de autenticación de GitHub al hacer push por HTTPS. Se diagnosticó que el repo se había clonado por HTTPS por defecto, mientras que los otros repos usaban SSH. Se cambió el remote a SSH con `git remote set-url` y el push funcionó a la primera. Se aprovechó también para añadir `.idea/` al `.gitignore`, que el template de GitHub para Java no incluye por defecto.

## Decisiones y aprendizajes

Se decidió no migrar la instalación de Claude Code del método npm (deprecado desde enero 2026) al native installer, aunque inicialmente se planteó lo contrario. La razón es que la instalación actual está sana, con auto-updates activados y sin síntomas de problemas reales. Migrar en la primera sesión de trabajo habría consumido tiempo y energía sin ganancia concreta. Queda anotado como deuda técnica menor a resolver en un hueco muerto futuro.

Se aprendió que un `CLAUDE.md` no es un fichero de configuración sino una carta al ingeniero nuevo que se incorpora al proyecto, y que su calidad determina la calidad del trabajo posterior con la herramienta. Se aprendió también que las bitácoras de aprendizaje sin "porque" son borrables sin pérdida, y que la disciplina de justificar decisiones en la propia bitácora es lo que la convierte en artefacto útil.

Se aprendió a leer el rango de hashes de `git push` (`51185b3..34e00d8  main -> main`) como confirmación explícita de qué commits se subieron, y a distinguir el estado local del estado remoto en Git.
